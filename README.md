# Шахматы

Проект реализует классические правила шахмат с поддержкой игры двух человек за одним компьютером и по локальной сети.

## Техническое задание

* **Язык и разметка:** C# и XAML
* **UI-фреймворк:** WPF
* **Архитектурный паттерн:** MVVM
* **Реактивное программирование:** ReactiveUI
* **Асинхронность:** `async/await`, `Task` и неблокирующий UI 
* **Сетевое взаимодействие:** `System.Net.Sockets` (`TcpListener` / `TcpClient`) + JSON-сериализация ходов

## Архитектура проекта

Проект разделен на логические слои для соблюдения принципов SOLID и подключения бота в будущем:

```text
Chess_game/
├── Models/                  # Чистая бизнес-логика шахмат (не зависит от UI)
│   ├── Board/               # Доска (8x8), клетки, координаты
│   ├── Pieces/              # Базовый класс Piece и наследники (Pawn, Rook, Knight, Bishop, Queen, King)
│   ├── Rules/               # Валидация ходов, проверка шаха, мата, пата, рокировки, взятия на проходе
│   └── GameState.cs         # Состояние партии (чей ход, история ходов, статус игры)
├── Services/                # Инфраструктурные сервисы
│   ├── GameModes/           # Паттерн Стратегия: IGameSession (LocalHotSeatSession, NetworkSession, будущем BotSession)
│   ├── Network/             # TCP-сервер и TCP-клиент для игры по локальной сети (LAN)
│   └── Audio/               # Звуковой отклик (ход, взятие, шах, недопустимый клик)
├── ViewModels/              # Реактивные ViewModel (ReactiveObject)
│   ├── MainViewModel.cs     # Навигация (Главное меню <-> Игровой экран)
│   ├── LobbyViewModel.cs    # Настройка игры: выбор режима, ввод IP для LAN или broadcast
│   ├── GameViewModel.cs     # Управление партией, таймеры, статус хода ("Ваш ход" / "Ожидание соперника")
│   └── CellViewModel.cs     # Состояние конкретной клетки (фигура, подсветка доступного хода, выделение)
└── Views/                   # XAML-представления
    ├── MainWindow.xaml
    ├── LobbyView.xaml
    └── GameView.xaml
```

## Ключевое архитектурное решение 

Чтобы безболезненно перейти от игры на одном ПК к игре по сети (а затем подключить бота), взаимодействие с доской строится через интерфейс `IGameSession`. `GameViewModel` не знает, кто делает ответный ход — второй человек за этим же экраном или игрок по сети; она просто реактивно подписывается на событие `OnMoveReceived`.

## Распределение задач в команде

Каждый участник отвечает за свой модуль.

### 1. Разработчик 1: Архитектор и Core-логика (Шахматное ядро)

**Зона ответственности:** Папка `Models/`.

**Задачи:**
* Проектирование структуры доски, фигур и базовых интерфейсов (`IGameSession`).
* Реализация генерации базовых ходов для всех 6 типов фигур.
* Реализация сложных правил: шах, мат, пат, запрет хода, оставляющего короля под шахом.
* Специальные правила: рокировка, превращение пешки, взятие на проходе.
* Написание Unit-тестов на логику правил.

### 2. Разработчик 2: UI/UX и XAML-верстка (View)

**Зона ответственности:** Папка `Views/`, стили, ресурсы (SVG/PNG фигур, звуки).

**Задачи:**
* Верстка главного меню (выбор режима: «1 на 1 на одном ПК», «Игра по локальной сети»).
* Верстка шахматной доски 8x8 на основе `ItemsControl` / `UniformGrid` с адаптивным масштабированием.
* Визуальная индикация: подсветка выбранной фигуры, точек возможных ходов, последнего хода и шаха королю.
* Оформление панели статуса: чей сейчас ход, индикатор ожидания в сетевой игре, модальное окно окончания игры (Победа/Поражение/Ничья).

### 3. Разработчик 3: Связующий слой и Реактивность (ViewModel)

**Зона ответственности:** Папка `ViewModels/` и `Services/Audio/`.

**Задачи:**
* Реализация `MainViewModel`, `GameViewModel` и `CellViewModel` на базе `ReactiveUI`.
* Обработка кликов пользователя через `ReactiveCommand`: выбор фигуры, попытка хода.
* Реализация разумного отклика интерфейса: воспроизведение звука ошибки при клике на чужую фигуру или пустую клетку, звука хода и взятия.
* Асинхронная связка моделей и UI без блокировки главного потока.

### 4. Разработчик 4: Сетевой модуль и Режимы игры (Network & Services)

**Зона ответственности:** Папка `Services/Network/` и `Services/GameModes/`.

**Задачи:**
* Реализация `LocalHotSeatSession` для первого этапа (игра 1 на 1 на одном экране).
* Разработка асинхронного TCP-клиента и TCP-сервера (`NetworkSession`) для обнаружения и подключения двух ПК в одной локальной сети (по IP и порту).
* Сериализация и передача ходов в формате JSON (например, `{"From": "E2", "To": "E4"}`).
* Обработка сетевых событий: синхронизация цвета фигур (хост — белые, клиент — черные), блокировка доски во время хода соперника, обработка обрыва связи.
